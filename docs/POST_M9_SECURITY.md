Boundaries: a browser cannot derive the launch secret through unauthenticated HTTP. Loopback TCP has no OS-user identity. A same-user malicious process that can read CIE memory, terminal, browser profile or files remains outside the web-session boundary; host-only HTTP cookies are host-scoped, not port-scoped, and HTTP loopback intentionally omits `Secure` for browser compatibility. Run under an isolated OS account for untrusted local users. Filesystem replacement races and unknown secret syntax remain open limitations.

Independent adversarial review reproduced a critical SEC-01 bypass in the first correction draft: Fastify decoded percent-encoded route segments for dispatch while an `onRequest` guard checked the un-decoded URL. Direct clients selected/analyzed a synthetic root and read its source without a cookie. The fix checks Fastify's matched route in `preHandler`, with encoded-route regressions for unauthorized GET, POST and missing-CSRF POST. Separate re-review against the corrected code returned 401 for encoded select, analyze, AI and source routes (including three encoded variants of a valid source URL); authenticated source access returned 200, and encoded mutations with a valid cookie but no CSRF returned 403. The bypass is closed in those bounded synthetic checks, not certified against every possible route encoding. A reviewed Vitest upgrade removed the critical tinypool finding; the high-severity audit passes, while two moderate minimatch toolchain paths remain for review.
