# CI security policy (SEC-04)

The existing [CI workflow](../.github/workflows/ci.yml) still runs the project checks with Node 22 and pnpm 10.34.8 from `package.json`. [Security](../.github/workflows/security.yml) runs on PRs targeting `main`, pushes to `main`, manual dispatch, and weekly. Do not use `pull_request_target` to execute contributor code. No provider credentials are needed or supplied. Checkout does not persist the workflow token; every job has read-only repository access except CodeQL, whose job alone gets `security-events: write` (plus `actions: read` for private-repository workflow metadata).

- **Dependencies:** `pnpm audit --audit-level high` checks the workspace lockfile, including development dependencies. High/critical advisories fail the job; moderate/low are reported and triaged, not silently declared safe. Dependabot proposes weekly npm/workspace and GitHub Actions updates; update the lockfile and run the full CI checks before merging. An unavailable audit service is a failed/inconclusive check, not a clean bill of health.
- **Secrets:** a checksum-verified upstream Gitleaks binary scans the **full Git history**, not just the latest diff. A temporary synthetic GitHub-token-shaped fixture must first produce exit status 1; fixture output is redacted, the fixture is outside the checkout, and it is never committed/uploaded. The repo scan uses `--redact` and fails on any finding outside the reviewed [baseline](../.github/gitleaks-baseline.json). The baseline has eight redacted historical findings in `apps/server/src/aiRedaction.test.ts` and `apps/server/src/ai.api.test.ts`: synthetic credential/redaction test material, not an exemption for those paths or for future commits. Each entry is tied to its original commit/rule/location; do not add broad path/rule allowlists. Before adding any exception, independently verify that the exact value is demonstrably synthetic and nonfunctional, document the rule, location, rationale, reviewer and date, and retain the narrowest possible fingerprint. If validity is uncertain, revoke/rotate and remove the material instead. Never publish unredacted scanner logs or real secrets in an exception.
- **CodeQL:** JavaScript/TypeScript `security-extended` analysis uploads findings to GitHub Code Scanning. Alerts need human triage; the analyze action succeeding does **not** mean zero alerts or automatically block a merge on findings. Enable code scanning and branch protection with required CI/Security checks in repository settings; private repositories may require GitHub code-scanning entitlement. Those settings cannot be established by this file alone.

Local check after a reviewed test-tool upgrade: the verified Gitleaks v8.18.4 binary detected the synthetic fixture, found eight historical findings (all covered by the narrow redacted baseline), and found seven current-tree hits in the same test-fixture files. The old Vitest 3.2.7 depended on vulnerable tinypool 1.1.1, and a first Vitest 4.0.0 trial still had a critical Vitest UI advisory. Both workspaces now pin Vitest 4.1.12 (Node 22-compatible); frozen-lockfile install, 245 server and 132 web tests, typecheck and lint passed. `pnpm audit --audit-level high` and `pnpm audit --prod --audit-level high` pass. `pnpm audit --audit-level moderate` reports two remaining development-toolchain paths for minimatch `<11.0.1` through ESLint and typescript-eslint (`GHSA-g3hv-75wg-m249`). Outcome: **needs review**, not an accepted exception; the dependency ranges use incompatible older minimatch majors, so do not force an untested major override. Review upstream compatible fixes, toolchain input exposure and owner risk decision before unrestricted release. Gitleaks v8.29.1/v8.30.1 did **not** detect this fixture in local tests, so the workflow pins the tested v8.18.4 archive and its SHA-256 rather than silently upgrading to an unproven scanner. Re-test the fixture and baseline when updating it. After pushing, inspect the exact-commit CodeQL run and GitHub Code Scanning alerts before claiming a hosted security result.
