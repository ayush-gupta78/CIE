# CIE

AI Codebase Intelligence Engine is a local-first codebase explorer. Select a local repository to map every eligible regular file in an interactive 3D atlas or 2D circular-node connectivity constellation. Verified connections appear only where a supported static analyzer can establish them; files without extractable relationships remain visible.

## Run locally

Prerequisites: Node.js 20.19+ and pnpm 10.34.8 (enable the pinned package manager with `corepack enable`). Verified on Node 24.19.0.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Open http://127.0.0.1:5173/; the Fastify API listens at http://127.0.0.1:3001/. Both bind to `127.0.0.1`; Vite proxies `/api` to the server. Stop both with Ctrl-C. Ports 5173 and 3001 must be free. The interface loads while the API is offline and reports connectivity accurately.

From the cinematic Archive home, choose **Open Local Repository** (or Repository in the top navigation), enter an absolute local folder path such as `/path/to/your/project`, then choose **Open repository**. Browsers cannot provide a normal folder input's absolute local path, so this manual path explicitly authorizes the local server to browse that directory. A `.git` folder is not required. Expand folders, select a file for basic metadata, use Load more for large directories, Refresh to see disk changes, Change repository to select another root, or Close repository to deselect without deleting any files. Selection lives in this server process only and is lost on restart. **Continue Current Session** enters the atlas only when such a selection exists; no recent-project history is stored.

Open **3D atlas** or **2D Graph** from navigation, or switch with **3D Map** / **2D Graph** inside the graph workspace. If this repository has no published graph, choose **Analyze repository**; switching modes never starts analysis. Both modes share one graph, search query, file selection, searchable directory tree, evidence workbench, inspector and file detail. Search by filename or relative path (press `/` to focus search); identical basenames remain distinguishable by their full paths. Choose any eligible file in the tree or scene, including isolated and unsupported files, or follow an evidence-backed relationship. **Open file details** reads permitted real source on demand, with numbered lines and static declaration context. The direction is referencing file → referenced file; selected outgoing links are gold and incoming links blue. Escape clears selection (or search focus).

In 3D, left-drag to orbit, right-drag/two fingers to pan, wheel/pinch to zoom; use directory focus, **Focus file**, **Fit view**, **Rotate view**, **Reset orientation** and **All labels**. Its camera retains orbit direction when the stage changes aspect. In 2D, click a small circular file to select it, drag empty map space to pan, wheel/pinch or **Zoom in** / **Zoom out**, **Fit view** for all files, **Focus selected** / **Focus file** for the selected file and its verified neighbors, or the directory focus buttons in the tree to frame a folder. Thin arrowed lines represent only verified, directed file references; selected outgoing links are gold, incoming blue, and unrelated lines dim rather than disappear. Muted cluster colors and captions follow real directory paths without enclosing panels. Hover a circle for full path, analysis status and relationship counts; the full path also appears for a selected file, in the keyboard-operable tree, SVG node name and inspector. At a dense overview most labels are suppressed to avoid collisions; search or zoom/focus to identify an individual file, including duplicate basenames and hollow unsupported files. Switching modes retains file/search/inspector state and each mode's viewport while the workspace stays open. The 2D map works without WebGL; if 3D fails, choose **Open 2D Graph**. Below 700px use **Files** and **Inspector** panel buttons and the mode-specific controls popover. Changing/refreshing a repository invalidates old graph and view state; after server restart reopen the repository. Re-analysis is explicit. Graph data is in server/browser memory, not persisted. Snapshot import remains unavailable.

Open **Findings** after selecting a repository. If no graph exists, use the explicit **Analyze repository** action; merely opening Findings does not analyze. The overview distinguishes verified declaration count from distinct directed file-to-file relationships, includes isolated files and analysis-status coverage, and never assigns a risk score. Search the file list by full relative path or basename, sort by direct/transitive incoming or outgoing connectivity, select a real file, and run change impact. Incoming dependents are files that reference the selected file; impact follows those incoming links to direct and indirect dependents, with a shortest explanation chain and paths to the existing 2D or 3D map. Circular dependency groups show directed verified members and a closed witness. A cycle-free result means no cycle was found among **known static** relationships, not that all runtime dependencies were analyzed. Unsupported, skipped, failed and partial files remain visible; a zero observed count is not proof of no dependencies. Findings and impact are tied to the graph manifest and discarded when repository identity or a successful reanalysis changes; a failed reanalysis retains the last published snapshot.

Use **View source declaration** on a verified connection in the inspector or Findings to open the referencing file at its captured line, with the referenced target and relationship type shown. Separate declarations to the same target have separate actions. A chain in change impact is displayed changed file → dependent, but each individual import declaration points dependent → referenced file. Source is live disk text, not stored analysis-time bytes: captured SHA-256 must match before an old line is highlighted. If it changed, re-analyze; metadata-only files without a captured hash show live source with freshness unverified, not proven evidence. Binary, invalid-UTF-8, inaccessible and over-budget files retain graph metadata and relationships without a code preview. Source inspection is read-only and never runs repository code.

## Optional assistant (M7; awaiting owner approval)

AI is off by default; no API key or network is needed for repository scanning, graph, Findings or source inspection. Open **Settings → Optional assistant** and choose OpenAI, a custom OpenAI-compatible HTTPS Chat Completions endpoint, or an explicitly local loopback HTTP endpoint. Custom endpoints accept an editable provider name, full request URL, model identifier and bearer key; local endpoints may use no authentication. Native Anthropic and Gemini protocols are not supported. Inspect the displayed destination, explicitly consent, enable requests and save. Changing the destination clears consent and the saved key; confirm the new destination and re-enter a key if needed, then save again. Keys remain in loopback-server process memory, are never returned by the status API, and are cleared on disable or consent withdrawal; restart also clears them. Test provider connection is a separate action and sends no repository source. Remote HTTPS providers receive source context only when explicitly asked. Local inference can keep content on this machine, but the configured local service remains its own security boundary. Obtain authorization before using confidential code: automated redaction cannot guarantee removal of every secret.

With an analyzed repository open, use **Assistant** in the graph workspace. A question may transmit the question, limited verified source excerpts and graph context to the configured endpoint. Selecting a file scopes file-specific questions; overview questions use repository-wide evidence. Ask is deliberate, Cancel aborts an in-progress request, and no conversation is saved after the workspace is closed or the graph snapshot changes. Answers are interpretations, not verified program behavior. Citations name graph file IDs and source lines; only evidence supplied to that request is eligible, and clicking a citation rechecks the manifest and live source before opening the existing file inspector. If the graph or source changed, re-analyze and ask again. Recognizable sensitive assignment values—including common camelCase, PascalCase, snake_case and quoted configuration names—are masked without dropping ordinary authentication code; private-key blocks are omitted with line numbers preserved. The answer shows screening/truncation warnings without exposing matched values. This heuristic cannot guarantee all secrets are found: review confidential repositories before sending evidence. Unsupported/binary files, unresolved references, runtime behavior and unverified live source cannot establish a verified answer. There are no automatic provider retries. The response output and context are bounded; actual charges depend on your provider account and are not estimated here.

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
pnpm format:check
```

The built server is `apps/server/dist/main.js`; the built static web app is `apps/web/dist/`. Production static hosting needs an equivalent same-origin `/api` proxy and its own security review; no hosted deployment is configured. `.github/workflows/ci.yml` runs these checks on GitHub push/PR for `main`; a local check does not establish remote CI success.

## API and security

`GET /api/v1/health` returns `{"status":"ok","mode":"local","version":"0.1.0"}`. Repository routes are:

- `GET /api/v1/repository`: current safe selection or `{ "selected": false }`.
- `POST /api/v1/repository/select`: JSON `{ "path": "/absolute/project/path" }` selects one directory; response includes only an opaque repository ID, revision and basename.
- `GET /api/v1/repository/tree?dir=.&repositoryId=<id>&revision=<n>&limit=100`: one level of real entries, directories first, with an opaque `nextCursor` for more pages. `dir` is `.` or a normalized repo-relative path. `limit` defaults to 100, maximum 200.
- `POST /api/v1/repository/rescan`: JSON `{}` advances revision; the UI reloads visible directory listings.
- `DELETE /api/v1/repository`: JSON `{}` clears selection, never touches disk.

State-changing requests require `Content-Type: application/json`. Expected errors use `{ "error": { "code": "INVALID_INPUT", "message": "..." } }` (also `FORBIDDEN_PATH`, `NOT_FOUND`, `STALE_REPOSITORY`, `NO_REPOSITORY_SELECTED`, `DIRECTORY_TOO_LARGE`, `IGNORE_TOO_LARGE`, `UNAVAILABLE`). The browser client requires matching repository ID/revision before accepting pages.

M2 graph API (same Host/Origin gate): `POST /api/v1/repository/analyze` with JSON `{ "repositoryId": "<selection ID>", "revision": <selection revision> }` captures and analyzes the selected root; `GET /api/v1/repository/graph` returns the last graph for that selection or `NO_GRAPH` (409). Use the `repositoryId` and `revision` returned by selection or `GET /api/v1/repository`. For example, with the local API running, select a trusted directory and inspect JSON with:

```sh
curl --noproxy '*' -sS -H 'Host: 127.0.0.1:3001' -H 'Content-Type: application/json' -d '{"path":"/path/to/your/project"}' http://127.0.0.1:3001/api/v1/repository/select
# Put the returned repositoryId and revision into the next JSON body.
curl --noproxy '*' -sS -H 'Host: 127.0.0.1:3001' -H 'Content-Type: application/json' -d '{"repositoryId":"<ID>","revision":1}' http://127.0.0.1:3001/api/v1/repository/analyze
curl --noproxy '*' -sS -H 'Host: 127.0.0.1:3001' http://127.0.0.1:3001/api/v1/repository/graph
```

M5 adds read-only `GET /api/v1/repository/insights?repositoryId=<id>&revision=<n>&manifest=<hash>` and `GET /api/v1/repository/impact?repositoryId=<id>&revision=<n>&manifest=<hash>&fileId=<id>` from that already-published graph. Supply the exact manifest returned by graph retrieval/analysis. A stale manifest or selection is rejected; impact requires a real file ID. No route rescans source files. Results include canonical file IDs, coverage, distinct relationship counts, cycle witnesses and reverse-dependency impact paths; they do not expose source bytes or execute project code.

M6 adds `GET /api/v1/repository/source?repositoryId=<id>&revision=<n>&manifest=<hash>&fileId=<id>`. The file ID must belong to the current published graph. Success returns the same identity, safe relative path/name, language/status, UTF-8 source text, line count and `freshness` (`verified` for matching captured SHA-256, `unverified` for metadata-only nodes). The route reads at most 256 KiB and 5,000 lines of one selected file; it has no arbitrary path or range parameter, no edit operation and no source execution. UTF-8 BOM is removed for display, invalid encoding and binary files are refused. The viewer highlights common JS/TS, Python, HTML/XML, CSS, JSON and shell syntax in smaller files; unknown formats and larger source display as plain text. `STALE_SOURCE` requires reanalysis when captured bytes no longer match; other failures use the standard structured error envelope. The existing exact Host/Origin gate applies. This is a local-process trust boundary, not a perfect filesystem sandbox against concurrent malicious replacement.

M7 adds `GET /api/v1/ai/config` (safe enabled/consent/preset/protocol/providerName/endpointUrl/model/authMode/local/hasKey metadata), `PUT /api/v1/ai/config` (JSON `{enabled,consent,preset,protocol:"openai-compatible",providerName,endpointUrl,model,authMode,local,apiKey?}`), `POST /api/v1/ai/test` with `{}`, and `POST /api/v1/ai/ask` with JSON `{repositoryId,revision,manifest,question,fileId?}`. `apiKey:null` clears a saved key; no key is needed for explicitly selected unauthenticated loopback mode. A destination change invalidates consent and credentials and requires a second save. Remote endpoint URLs must be HTTPS with a validated public IPv4 destination; local HTTP is restricted to loopback. Remote DNS answers with special-use addresses, including non-public IPv6, are rejected as a whole; IPv6-only providers are not supported. No URL credentials, query/fragment, redirects or arbitrary LAN destinations are allowed. `revision` is a number, `fileId` is the graph's SHA-256 path identity, and `manifest` must match the current published graph. Ask returns snapshot identity, answer, limited citations, grounding status, limitations and warnings; `cited` confirms a quoted supplied source line, **not** semantic correctness of every sentence. The existing loopback Host/Origin and JSON gates protect these routes. No browser-provided absolute source path, arbitrary source range or provider tool invocation is accepted.

All permitted regular files, including binary assets, documentation, hidden and extensionless files, receive stable path-ID nodes and actual metadata. Unsupported dependency formats remain visible with `unsupported` status; `partial`, `failed` and `skipped` distinguish incomplete parsing, failures and size/encoding limits. JS/JSX/TS/TSX/MJS/CJS/MTS/CTS retain TypeScript AST parsing for top-level static imports/reexports. Conservative additional adapters resolve exact unique local files for Python relative `from` imports, Java class imports in conventional source roots, quoted C/C++ includes, Rust `mod` declarations, HTML local references and CSS imports/asset URLs; their coverage is explicitly partial. C/C++ commented-out, string-contained and provably inactive includes cannot create edges; macro-dependent conditional includes remain unverified and emit diagnostics rather than guessed edges. Bare/external, unresolved and ambiguous constructs never form verified file edges. Graph schema v1 adds category, text/binary/unknown kind, size and resolved incoming/outgoing counts; `analyzerVersion` is `m3-universal-2` after the conservative C/C++ correction. An optional source SHA-256 is present only when bytes were captured; each verified edge cites captured source path/line/column/hash. Metadata-only files are not loaded for parsing. The analysis rejects more than 200 eligible files, 1,000 directories, 1,000 edges or 10 seconds at checkpoints rather than publishing a truncated graph. Parser input is capped at 1 MiB/file and 8 MiB total; oversized non-JS files remain visible with skipped-analysis status, while existing JS/TS limits reject reanalysis. No tsconfig-alias resolver, persistent snapshot, incremental index, or universal dependency parser exists. See ADR-025 for metadata-only manifest tradeoffs. The parser and scanner tests run in `pnpm test` (`apps/server/src/graph*.test.ts`).

The API restricts Host to `127.0.0.1:3001` or `127.0.0.1:5173`, and supplied Origin to the matching HTTP loopback origins. An absent Origin is allowed for CLI clients with an approved Host. No broad CORS. Root selection is deliberate and in-memory, a selected symlink root is refused, descendants are never followed through symlinks, and subsequent paths undergo lexical and canonical containment checks. The tree browser receives names, relative paths and metadata; the graph response additionally exposes import specifiers and fingerprints but no full source content or absolute root paths. The separate M6 source route serves one authorized graph file on demand. This is not a sandbox against malicious local processes or a complete defense against filesystem TOCTOU replacement races.

Generated directories (`.git`, `node_modules`, `dist`, `build`, `coverage`, `.next`, `.turbo`, `.cache`) are always hidden. `.env*` is hidden by default, except `.env.example`. Root and nested `.gitignore` rules use the `ignore` library with negation; rules inside an ignored parent cannot make that parent browsable. Git index tracking, global excludes and `.git/info/exclude` are not consulted. Each directory is loaded lazily, capped at 5,000 scanned entries with a 200-entry maximum page and 256 KiB per ignore file; oversized directories/rules return a structured error rather than being partially represented. Refresh is manual, not a filesystem watcher. Filenames containing literal backslashes or percent escapes cannot be navigated as directory paths by this API. Windows/UNC path behavior has not been verified on Windows.

## Structure and scope

- `apps/web/`: React/Vite shell, repository tree, validated graph/Findings clients, M3 Three.js spatial view and M4 WebGL-free SVG file map.
- `apps/server/`: Fastify HTTP gate, in-memory selection, bounded filesystem explorer, graph API and M5 deterministic structural findings.
- `ARCHITECTURE.md`: living data flow, trust boundaries, roadmap and append-only decisions.
- `docs/UI_DESIGN_SPEC.md`: current six-reference design decision plus historical guidance; `docs/screenshots/`: final browser captures and prior M3 evidence.

Archive, Repository, 3D atlas, 2D Graph, Findings, Assistant and Settings navigation work. M0–M6 are owner-approved per the M7 handoff; the M7 correction awaits independent review and owner approval. Native non-compatible provider adapters, scalability, expanded language analysis, embeddings and agentic editing remain deferred. No signup, telemetry or cloud-hosted repository storage is required. The newer six-image visual handoff resides locally under ignored `prompts/m3-visual-redesign/references/`; implemented-app captures are in `docs/screenshots/`. The Home background is an original generated illustration bundled with the app rather than an approved screenshot used as a facade.
